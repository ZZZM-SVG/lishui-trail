# 演示脚本（3—5 分钟）

> 目标：在有限时间内讲清「问题 → AGH 底座 → 数据连接 → 规划与风险 → 可复现」这条闭环。
> 建议全程录屏，右侧露出 AGH 会话中的**工具调用记录**（这是"用了 AGH"的最直接证据）。
>
> 📌 录制时照着念的台本（含操作提示、彩排参数、口播禁忌）见 [`演示提词卡.md`](演示提词卡.md)；
> 片头画面见 [`片头标题卡.html`](片头标题卡.html)；调用过程回放见 [`evidence/会话回放.html`](evidence/会话回放.html)。

## 0:00—0:30｜一句话立题

**画面**：溧水水乡航拍/地图底图 + 标题《诗画溧水·水韵慢城——城郊文旅线路智能规划系统》。

**旁白**：
> 溧水有 162 个文旅资源锚点，但导航只能给"点对点最短路径"。
> 我们有 4 小时、体力一般、还带着孩子——今天该走哪几处？哪几处值得深看？
> 会不会穿过水库？日落前走得完吗？
> 我们做了一个**完全离线、只用 AGH 与 Agnes 模型**的系统来回答这些问题。

---

## 0:30—1:10｜AGH 作为底座 + 数据连接

**画面**：终端/Web 里 AGH 插件管理页，显示 `lishui-trail` 已信任并启用；
侧栏会话中依次出现 `lishui_trail_status` 的调用记录。

**旁白**：
> 所有能力都封装成一个 AGH 插件，通过扩展行注册了 6 个工具。
> 先用 `status` 让 Agent 自己确认数据是否就绪——这是 AGH 连接数据的第一步。

**要点字幕**：
- 数据集：162 锚点 / 698 资源单体 / 49 虚拟对象
- 数字孪生：2149×1511 @30 m 高程栅格 + 2523 条路网 + 839 处水域
- 全部离线，零外部依赖，不调用任何外部模型

## 1:10—2:20｜个性化规划（核心演示）

**画面**：输入自然语言画像 → Agent 调用 `lishui_trail_plan` → 展开结构化结果。

**输入示例**：
> 我想走慢城水乡，看古村老街，顺便体验非遗和乡野采摘。体力一般，带着孩子，只有 5 小时，
> 10 月 18 日早上 8:30 出发。

**旁白**：
> Agnes 模型把这段话翻译成画像参数：兴趣权重、体能档位、同行人员、时间预算、出发时刻。
> 插件把它建成一个**带预算的定向越野问题**：贪心插入 → 2-opt/Or-opt → 模拟退火多次重启，
> 再用真实地形几何回代校验预算，放不下的点按"单位收益耗时"降级或剔除，最后把真实几何下放得下的点回填回来。

**展示结果**：
```
环线 3 站｜12.9 km｜累计爬升 100 m｜总耗时 278/300 分钟（93%）｜风险 36/100（较低）
深度游览 2 站 + 快速打卡 1 站
无想山景区（集合点）→ 无想水镇·城隍庙街区 → 郭兴庄园 → 世豪农业水蜜桃基地
自校验 12 项：通过 12，警告 0，失败 0
```

**对比演示（体现"个性化"）**：
切换画像 →「摄影打卡 / 体力强健 / 6 小时」与「历史人文 / 带老人 / 3 小时」，
结果点位与顺序明显不同。

**画面（推荐双屏，这段的"眼缘"全靠它）**：
右侧同屏打开**离线演示台**（仓库根目录 `start.cmd` 双击启动；现场不便起本地服务时，
可直接打开在线演示台 <https://lishui-tour-planner.app.workbuddy.host/>，内容与本机完全一致）：
同一画像在地图上实时画出路线、停靠点序号、风险雷达与 12 项自校验，
并可现场改预算/拖必去点再点一次「生成方案」——秒级出结果。
要向评审说清一句话：**演示台是 AGH 插件的视图层，与插件共用同一份求解器，
本页不做任何模型调用**；模型的自然语言交互仍走左侧 AGH 会话。

## 2:20—3:00｜风险预判

**画面**：调用 `lishui_trail_risk`，展开七因子与证据。

**旁白**：
> 风险不是一个拍脑袋的分数，而是七个因子的加权：地形坡度、气象季节、日照时段、涉水湿滑、
> 偏远救援、通行可达、体能匹配。权重会随同行人员和季节自适应。

**要点字幕**：
- 关键证据：最大坡度 / 陡坡占比 / 最近水域 / 离步道最远距离 / 日落余量
- 分级缓解建议（例如：同行含儿童 → 收紧坡度与爬升上限）

## 3:00—3:30｜异常处置 + 成果落地

**画面**：先 `lishui_trail_alternatives`（第 2 站关闭 → 推荐 3 个同类点），
再 `lishui_trail_export` 导出 GPX，并由 AGH 自身文件工具写入 `lishui-trail.gpx`，
最后把 GPX 拖进两步路/Strava 展示轨迹。

**旁白**：
> 外部条件变化时，Agent 不必重新描述需求——只要调用替代点工具就能快速改线。
> 规划结果可以导出标准 GPX，直接进手机导航。

## 3:30—4:20｜可复现与自校验（作品的技术底色）

**画面**：命令行运行 `node tests/smoke.mjs`，滚动显示 12 项自校验。

**旁白**：
> 我们不相信"看起来很顺"的方案。系统会**独立于求解器**重算 12 项指标：
> 距离、爬升、分段统计、时间预算、坡度约束、必去/避开点、停靠点可解析、风险阈值，
> 以及**同种子几何哈希一致**——这一项每次调用都真跑（同输入再解一次、比对哈希），不是写在文档里的承诺。

**字幕**：`12 项检查：通过 12，警告 0，失败 0`

**再加一段"失败也要说清楚"（约 20 秒，很能加分）**：
> 把预算压到 60 分钟、还要求必去两个相距很远的点，系统不会硬凑一条看起来能走的路线，
> 也不会抛异常——它会直接告诉你：是哪两个必去点放不进去、为什么，以及可以怎么改。

**画面**：`node tests/case_matrix.mjs` 滚动，停在 `[13][失败]` 那两行（`reason` + `hint`）。

## 4:20—5:00｜收尾

**旁白**：
> 这是一个**离线本地、只用 AGH 与 Agnes 模型**的系统：AGH 负责执行与工具编排，
> Agnes 负责理解与表达，本地的算法负责把地理空间数据变成可走的路线和可信的风险判断。
> 它不只服务溧水——把数据换成别的区县，同一套引擎即可复用。

**画面**：项目目录树 + 赛项三条要求逐条打勾。

  并在口播中说明平台差异（见 `docs/AGH接入说明.md` 第 6 节）。
- **不必现场重跑 AGH**：主证据会话已经跑完并归档，展示"调用过程"用
  `docs/evidence/会话回放.html`——点「▶ 播放」即按真实顺序逐条演：用户指令 → 工具调用
  （工具名 / 参数 / 只读与联网策略 / 耗时 / `verifier: pass`）→ 结构化返回 → Agnes 作答。
  要停留讲解就点「下一步」逐条推进，录错了点「↺ 重播」，紧张时切 2× 走完再用 1× 补特写。
  页面角标已注明"真实会话记录 · 非实时"，口播时照念即可，反而比现场跑更可信（可反复核验）。
